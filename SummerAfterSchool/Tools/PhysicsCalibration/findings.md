# 翻片物理校准结论

2026-10-03，Unity `6000.3.25f1`，PhysX，固定步长 `0.01 s`。

校准调用正式 `DiscBody.Spawn`，使用同一个 48 边凸圆柱碰撞体、`mass = .08 * weight`、厚度、质心、摩擦与阻尼。空的编辑器场景只保留水平地面，地面摩擦 `.58`。模拟通过 `PhysicsScene.Simulate` 推进，没有直接设置目标翻面朝向。

## 核心问题

1. 原本的衰减后垂直冲量常常只有 `.06～.08 N·s`。普通厚纸片在 `lever=.25` 时，需要约 `.115～.15 N·s` 才能越过翻面门槛；`.10` 及以下只会晃动后落回正面。
2. 首次碰撞时出手片位于目标上方。立刻给目标向上冲量，会被两张圆片之间的接触解算压回去。轨迹测试 `power=.42` 对薄纸片施加 `.109 N·s`，目标最大高度只有 `.119 m`，最终仍是正面。单独圆片对照说明，同等级冲量已经有翻转能量。
3. 把触发条件从 `striker.y<.4` 放宽到 `.7` 没有帮助：已观测到首次有效撞击高度为 `.189/.191`，原条件本来就成立。
4. 更大的力并不保证成功。过大的冲量会转过两圈后重新落回正面，这是当前刚体的真实行为。

## 正式掌拍参数

记录第一次撞击位置，等待 `.095 s` 的游戏时间，让接触中的两张片分开，然后按目标当时的位置重新算衰减。

```csharp
float falloff = Mathf.Pow(1f - distance / 1.3f, .25f);
float liftImpulse = target.Weight * (.125f + shotPower * .025f) * falloff;
Vector3 impulse = Vector3.up * liftImpulse
    + away * .06f * (.32f + shotPower * .68f) * falloff;
Vector3 edge = target.Body.position - away * (.23f + target.EdgeLift * .045f);
target.Body.AddForceAtPosition(impulse, edge, ForceMode.Impulse);
```

等待时间随游戏暂停停止，`StopMatch()` 清理待施加的脉冲。以上是当前正式掌拍公式；下面较高峰值的表格为早期扫描对照。重拍与斜擦分别保留自己的力度与传播方式。

## 实测全轨迹对照

出手片使用初始薄纸片，目标阵列使用正式 `artIndex=5…9` 与当前游戏位置，力道朝最左前方目标；模拟 15 秒，得分只看最终刚体法线是否低于 `-.84`。

| 力道 | 原参数，当帧脉冲 | 早期质量归一公式，延后 95 ms |
| --- | ---: | ---: |
| .32 | 0 | 0 |
| .42 | 0 | 1 |
| .58 | 1 | 2 |
| .72 | 0 | 2 |
| .92 | 0 | 1 |

该早期对照公式为 `.17 + .065 * power`、衰减指数 `.75`；在 `.42` 力道时能停稳翻下一张薄纸片，`.58` 与 `.72` 可真实双翻。正式参数后来降低了峰值并减缓衰减，以扩大普通厚片的单翻范围。不同落点、已移动阵列与玩家拖拽仍会改变结果。

## 连续回合补充与运行态差异

另扫描了 9 组最多 9 手的连续回合，每手重新瞄准 `z` 最靠前的未得分圆片，并在物理停稳后检查结果。

| 公式 | 角阻尼 .65 | 角阻尼 1.3 | 角阻尼 2 |
| --- | ---: | ---: | ---: |
| `.17 + .065 * power`，衰减指数 `.75` | 3 | 3 | 3 |
| `.125 + .025 * power`，衰减指数 `.25` | 3 | 3 | 3 |
| `.135 + .020 * power`，衰减指数 `.25` | 3 | 3 | 2 |

较低峰值和较平衰减可把普通厚片带到单次翻面的能量范围；提高角阻尼并没有整体改善成功率。编辑器的结果与同期 Windows Player 的逐帧结果存在明显差异，因此正式游戏应继续以原生玩家中的碰撞位置、脉冲、最低法线和最大高度记录校准，不能只根据这个编辑器序列宣称游戏已经获得相同手感。

已修复的运行态差异是正式出手片从低位的 kinematic 刚体切换为动态刚体，且启用了插值；校准是在高位直接创建动态刚体。运行态现在使用 `Rigidbody.position` / `Rigidbody.rotation` 设置出手姿态，并调用 `Physics.SyncTransforms()`，避免插值系统中的 Transform 与原生物理姿态不同步。最终 Windows Player 三手掌拍依次获得 1、2、3 分，以 3:0 完成练习，并验证暂停后继续的得分与模式。

## 斜擦与完整出圈

斜擦从贴地位置开始，仅在碰到目标圆片时触发水平气流；发射点的地面接触不消耗这次推力。水平推力在 `.01 s` 后施加，传播距离按接触边缘计算：`max(0, centreDistance - target.Radius - striker.Radius)`。NPC 在出圈规则下也选择斜擦，并根据目标距离调整力度。

最终 Windows Player 的真实赌片出圈局获得 `2:3`，约定实例按实际结果转手，pending 清除，完整运行报告 `errors=[]`。得分仍然要求圆片停稳后整张越过边界。报告见 `Logs/QA/Runtime/runtime-report.json`，没有动画设定翻面或强行搬片出圈。
